## 5. 끝내기 전 점검표
- [ ] `open` 이 비어 있었으면 아무것도 하지 않았다(파일·알림·커밋 없음).
- [ ] 요청마다 원인을 실행 번호·시각으로 댈 수 있다. 실패한 실행이 있었는지 확인했다.
- [ ] 고친 것은 요청과 직접 닿은 것뿐이다. 고친 뒤 한 번 돌려 성공을 봤다(KRX 로그인 워크플로는 한 번만).
- [ ] 화면을 고쳤다면 웹판과 claude.ai 대시보드 둘 다 고쳤다(못 했으면 "claude.ai 쪽 미반영").
- [ ] `watchdog` 실행 뒤 `open` 이 빈 목록인지 봤다. `repair_request.json` 은 내가 고치지 않았다.
- [ ] repair_log 맨 위에 문제·원인·표·확인 결과·남은 일을 적었다.
- [ ] alerts/repair.txt 를 통째로 새로 썼고 통마다 200자 이내다.
- [ ] 구조·기준 변경, 비밀값, 요청 밖 문제는 고치지 않고 적기만 했다.

## 6. 하지 말 것
- 비밀값(KRX·DART·Kakao·TwelveData·Tavily)을 읽거나 쓰지 않는다. 비밀값 문제로 보이면 "비밀값 확인 필요"만.
- KRX 요청 속도를 줄이거나 동시 수집을 만들지 않는다. 선물·옵션 수집(collect.py·trigger.txt)을 건드리지 않는다.
- 연구소의 통과·관찰 기준, 실전 확인 단계 숫자, `round*.json`·`state*/`·`out*/` 을 고치지 않는다.
- 미국 옵션 추정 방법(비율 k·벽 정의)을 바꾸지 않는다. 원자료를 추정으로 채우지 않는다. 노랑 신호를 만들지 않는다.
- 요청과 상관없는 개선·정리를 하지 않는다. 업그레이드 요청은 `do` 밖의 일을 하지 않는다.
- Claude 예약 작업(모델·일정·켜짐·본문)을 바꾸지 않는다. `state/repair_request.json` 을 고치지 않는다.
- 도구가 거부하면 우회하지 않는다. 사용량 한도에 닿으면 멈춘다.
